# LF_UIProbe

A source-only, first-party client probe that needs no Dabs Framework. It asks
DayZDiag two layout questions: does a leaf widget with no child block load, and
what text does a line continuation between two quoted strings produce.

## Preparation

The repository normalizes text to LF, so the CRLF variant is not kept in the
repository. It is generated byte for byte in a new directory.

```powershell
python scripts/tools/dayz-ui-lab/probe/prepare_probe.py `
  --out reports/dayz-ui-lab/probe/LF_UIProbe
```

The preparer fails if the destination already exists. The result contains:

- `leaf-without-child-block.layout`;
- `continuation-lf.layout`;
- `continuation-crlf.layout`;
- a client mod that requires only vanilla addons and loads all three fixtures
  once.

## Required evidence

Run the staged mod in DayZDiag. Keep the RPT span between:

- `[LF_UI_PROBE_BEGIN]`
- `[LF_UI_PROBE_END]`

The `LF_UI_PROBE_RESULT` lines report the text returned by
`ButtonWidget.GetText(out string)`. The probe has no hardcoded expected value:
the continuation behaviour can only be settled after observing both the LF and
the CRLF case in the engine. Do not use the offline parser as a substitute for
that observation.
