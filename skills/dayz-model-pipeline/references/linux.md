# Running the model pipeline on Linux

What changes for this skill on Linux. Agentic-Z is a Windows workspace and its DayZ skills (`/dayz-build-pbo`, `/dayz-launch-test`, `/dayz-preflight`) assume Windows and DayZ Tools; everything in the other reference files is the Windows workflow and stays valid there. The notes below describe a Debian setup with Proton and were not run on this workspace. This is tool behavior, so nothing here is checked on `P:\`.

The Proton setup, the measured tool matrix and the pitfalls are in the shared Linux and Proton notes (`skills/_shared/linux-proton.md`, with the helper scripts `skills/_shared/scripts/dayz-proton.sh` and `skills/_shared/scripts/dayz-mod-pack.sh`); this file only says what changes for the model pipeline.

- **Install Blender and the noise library** with the system's package tools, on Debian: `apt-get install -y blender` and `pip install opensimplex --break-system-packages`, then py3d with `pip install -e scripts/tools/py3d`.
- **Pack, sign and binarize with dayzmake 2.0.0 or later.** dayzmake is a DayZ build tool derived from armake2, pinned to `v2.0.0`: install the `v2.0.0` release binary or build that tag with cargo, as the shared Linux and Proton notes describe. `v1.0.0` builds and signs your own mod, but unpacking a PBO you did not build needs `v2.0.0` or later. Use `dayzmake build`, `keygen`, `sign`, and `build --proton-binarize` where needed. Plain armake2 is no substitute: it is built for Arma, its V3 file hash omits `*.c` files (dayzmake v1.0.0 includes them) and it lacks the DayZ only functions dayzmake keeps adding. The helper script `dayz-mod-pack.sh` wraps these commands (`init`, `keygen`, `build [--binarize-models]`, `check`, `publish-hint`). A textured cube binarized through `--proton-binarize` with fork commit `7dcb3cf`, built before the rename and still called armake2, matched the output of Bohemia's binarize from a `P:` root byte for byte. dayzmake `v1.0.0` contains that commit, but the comparison was not repeated with a dayzmake release binary. That is a file comparison, not an in-game ODOL check.
- **`P:\` is a plain directory.** `dayz-proton.sh init <dir>` maps it; a `P:\<Mod>\...` path in this skill is `<dir>/<Mod>/...` there.
- **Object Builder and TexView run under Proton**: `dayz-proton.sh gui ObjectBuilder <p3d>` and `dayz-proton.sh gui TexView <paa>`. Object Builder opened and displayed a model; editing in it was not exercised.
- **Offline checks run natively.** py3d (`scripts/tools/py3d`), the model preflight tool (`scripts/tools/dayz-model-preflight`) and the 3D viewer (`scripts/tools/dayz-3d-viewer`) are Python.
- **In-game checks** follow the Linux notes of the `dayz-test-ingame` skill (`skills/dayz-test-ingame/references/linux.md`).
