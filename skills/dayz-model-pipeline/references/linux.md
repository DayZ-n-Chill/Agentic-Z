# Running the model pipeline on Linux

What changes for this skill on Linux. Agentic-Z is a Windows workspace and its DayZ skills (`/dayz-build-pbo`, `/dayz-launch-test`, `/dayz-preflight`) assume Windows and DayZ Tools; everything in the other reference files is the Windows workflow and stays valid there. The notes below come from the source author's own Linux setup and were not run in this repo. This is tool behavior, so nothing here is checked on `P:\`.

The Proton setup, the measured tool matrix and the pitfalls are in the Linux notes the same import brings in (`linux-proton.md`, with the helper scripts `dayz-proton.sh` and `dayz-mod-pack.sh`); this file only says what changes for the model pipeline.

- **Install Blender and the noise library** with the system's package tools, as the source did on Debian: `apt-get install -y blender` and `pip install opensimplex --break-system-packages`, then the py3d fork with `pip install -e scripts/tools/py3d`.
- **Pack, sign and binarize with dayzmake 1.0.0 or later.** dayzmake is bzed's DayZ fork of armake2 (https://github.com/bzed/dayzmake), pinned to `v1.0.0`: the release binary `dayzmake-v1.0.0-debian-trixie-x86_64.tar.gz` from https://github.com/bzed/dayzmake/releases/tag/v1.0.0, or `cargo install --git https://github.com/bzed/dayzmake --tag v1.0.0`. Use `dayzmake build`, `keygen`, `sign`, and `build --proton-binarize` where needed. Upstream armake2 is no substitute: it is built for Arma, its V3 file hash omits `*.c` files (dayzmake v1.0.0 includes them) and it lacks the DayZ only functions dayzmake keeps adding. The helper script `dayz-mod-pack.sh` wraps these commands (`init`, `keygen`, `build [--binarize-models]`, `check`, `publish-hint`). The author's textured cube comparison of 2026-11-03 with Bohemia's binarize from a `P:` root matched byte for byte (fork commit `7dcb3cf`, then still named armake2; `v1.0.0` contains it). That is a file comparison, not an in-game ODOL check.
- **`P:\` is a plain directory.** `dayz-proton.sh init <dir>` maps it; a `P:\<Mod>\...` path in this skill is `<dir>/<Mod>/...` there.
- **Object Builder and TexView run under Proton**: `dayz-proton.sh gui ObjectBuilder <p3d>` and `dayz-proton.sh gui TexView <paa>`. Object Builder opened and displayed a model; editing in it was not exercised.
- **Offline checks run natively.** py3d (`scripts/tools/py3d`), the model preflight tool (`scripts/tools/dayz-model-preflight`) and the 3D viewer (`scripts/tools/dayz-3d-viewer`) are Python.
- **In-game checks** follow the Linux notes of the in-game test material from the same import.
