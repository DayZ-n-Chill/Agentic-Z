Agentic-Z Guide

Reference for installing, configuring and using Agentic-Z, the AI agent stack for DayZ modding. This edition covers version 2.0.0: 30 agents, 44 skills, three hooks and a side panel plugin.

Overview

Agentic-Z is a Claude Code plugin and repo template for DayZ modding. It adds DayZ specialist agents, skills (slash commands) that drive DayZ Tools, rules files for mod conventions, and the dayz-rag MCP server, which searches the vanilla game files so agents cite real files instead of guessing.

Architecture

The AI tool loads the rules, agents and skills and calls the dayz-rag MCP server. These act on the mod folder, the P: drive, DayZ Tools and the game, and the search index on disk.

Setup wizard

/dayz-init

On first run the wizard asks for: new mod or import, the mod name, the test map, and whether to build and launch. It fixes what it can (mounts P:, creates the P:\Mods link) and prints the fix for the rest. Later runs open a status hub for the active mod.

Build loop

  1. Ask an agent for the change, for example "add a hidden selection for the camo".
  2. /dayz-build-pbo <ModName> packs the mod into P:\Mods\@<ModName>\Addons\.
  3. /dayz-launch-test <ModName> --server <instance> starts a DayZ Diag server and client with the mod loaded.
  4. Read the logs (locations in "File layout"), or pass them to dayz-mod-debugger.
  5. /dayz-stop-test stops every DayZDiag_x64.exe process.

Gates

dayz-orchestrator runs a full mod build as the main session. Start it with claude --agent agentic-z:dayz-orchestrator (plugin) or claude --agent dayz-orchestrator (clone). It plans the mod with dayz-mod-architect, waits for your approval, then runs the work in waves. Each wave passes these gates in order; who runs which gate is in "Team structure".

GateRunsChecks
Mod review (dayz-mod-reviewer)Every taskConvention compliance and common defects; read only.
Layout check (dayz-layout-validator)Every .layout changeThe Figma-to-DayZ rules; read only.
Build (/dayz-gate build)Once per wave/dayz-lint, then AddonBuilder output.
In-game (/dayz-gate ingame)Once per waveServer and client logs after the client joins the mission.
Behavior (/dayz-gate behavior)Once per wave, when output\<ModName>-plan\behavior-checks.json existsA scripted mission spawns and uses each new item.

/dayz-gate prints its verdict on the first line: PASS (exit 0), FAIL (exit 1) or ERROR (exit 2). On an ERROR from the gate script itself, the orchestrator falls back to dayz-build-checker or dayz-ingame-tester; the behavior gate has no fallback agent. Nothing reaches you until it builds, loads in game with clean logs and, when the plan lists behavior checks, passes the behavior gate.

RAG search

The dayz-rag MCP server searches an index of the vanilla files on P:. /dayz-search-index builds the index with Voyage AI embeddings (voyage-code-3 by default) into LanceDB at ~\.claude\dayz-search-index\. /dayz-search-download installs a prebuilt index instead; it is older than the current indexer. Searching still needs VOYAGE_API_KEY, because each query is embedded through the Voyage AI API.

MCP toolFunction
search_dayz_sourceSearches vanilla scripts, configs, layouts and materials by meaning.
get_dayz_fileOpens an exact file and line range on P:.
list_indexed_sourcesLists what is indexed and when.

Lookup order: agents Grep first when they know an exact class or symbol name, and use RAG search for questions by meaning or after two or three failed greps. A hit is a hint until the agent opens the real file, so answers cite path:line.

Rule tiers

Tier 2 is .claude/skills/_shared/dayz-conventions.md (143 lines) plus five topic files in conventions/: config.md, assets.md, scripts.md, ui.md and server.md. After you correct an agent, /dayz-record-correction writes the rule into the right tier once you approve it.

Domain specialists

Eight specialists cover saving data, vehicles, weapons, wearables, animation, audio and FX, physics and AI, alongside the script, config, art, UI, map and server workers. Each works under a team lead and has its own knowledge pack, checked against the vanilla game files and loaded only when a task needs it. The one-line index is in "Agents"; the tables below give each one's scope and output.

Specialist reference

dayz-persistence-specialist
ScopeKeeps modded items and systems' data across server restarts. Writes the save and load code (OnStoreSave and OnStoreLoad), stamps every save with a version number, and writes the upgrade path so old saves still load after the mod changes. Covers base building parts that must survive restarts. Before release it runs a data audit that checks every saved field is written and read back in the same order.
Example request"Make my safe keep its code and contents after a restart, and do not break saves from the last version."
LeadScript lead (the release audit goes to the server lead)
ReturnsSave and load code with a version number, a migration note for old saves, and an audit report for the server lead.
dayz-vehicle-specialist
ScopeCars, boats and helicopters: the vehicle class and its simulation (engine, gearbox, axles, wheels), attached parts (doors, hood, trunk, wheels, battery, spark plug), fluids (fuel, oil, coolant, brake fluid), seats and crew positions, and damage. Vanilla DayZ ships native helicopter base classes (Helicopter, HelicopterAuto and HelicopterScript) but no flyable helicopter, so flyable ones are built on those classes with the user's own code, never copied from another mod.
Example request"Add a four door pickup with its own doors and a bigger fuel tank."
LeadConfig lead
ReturnsCfgVehicles entries, the CarScript, BoatScript or HelicopterScript class, attachment slots, and a types.xml entry for the server lead.
dayz-weapon-specialist
ScopeFirearms: the weapon class, magazines, ammunition, attachment slots (optics, suppressors, stocks, handguards), recoil, fire modes and muzzle effects. Inherits from the closest vanilla weapon so reloading, jamming and damage behave like the base game.
Example request"Add a scoped hunting rifle that takes a five round magazine and the vanilla long range optics."
LeadConfig lead
ReturnsCfgWeapons, CfgMagazines and CfgAmmo entries, a recoil class, and the model selections the art lead must provide.
dayz-wearables-specialist
ScopeClothing, gear and characters: inventory slot, slots held, protection and insulation, hidden selections that let one model carry several textures, and display on the character through proxies. Covers new survivor characters.
Example request"Make a plate carrier with three colors that fits the vest slot and holds six items."
LeadArt lead
ReturnsConfig entries, hidden selection names, texture slots for each color, and proxy notes for dayz-object-builder.
dayz-animation-specialist
ScopeMoving parts such as doors, lids, hatches and triggers. Writes the skeletonBones for the moving parts and the class Animations block in model.cfg (rotations, movements, hiding parts); dayz-object-builder keeps the rest of model.cfg. Handles .rtm animation files and writes the Blender handoff so bones and selections line up in Object Builder.
Example request"Make the doors on my bunker open and close when a player uses them."
LeadArt lead
ReturnsThe skeletonBones and class Animations entries, the selection and bone names the model needs, and the script hook that plays the animation, for dayz-script-specialist to write.
dayz-audio-fx-specialist
ScopeSound shaders and sound sets, sound range and volume, and particle effects such as smoke, sparks and muzzle flashes. Uses the /dayz-particles skill for particle files.
Example request"Give my generator a running sound that fades with distance and a puff of exhaust smoke."
LeadAny lead
ReturnsCfgSoundShaders and CfgSoundSets entries, particle files, and the script lines that play them.
dayz-physics-specialist
ScopeWeight, collision shapes in the Geometry and Fire Geometry LODs, how objects land when dropped or thrown, and contact with players and vehicles. Diagnoses common faults such as items falling through floors or bullets passing through walls.
Example request"My crate falls through the floor when I drop it. Fix it."
LeadAny lead
ReturnsGeometry and mass fixes for dayz-object-builder and config changes for the config lead.
dayz-ai-specialist
ScopeBehavior for computer controlled characters: infected, animals and human AI such as patrols and guards. Studies the patterns other modders use, then writes the user's own version; nothing is copied from another mod.
Example request"Add a patrol of guards that walk a route around my military base and react to gunfire."
LeadScript lead
ReturnsScript classes for the behavior, the config the server lead needs to spawn them, and server performance notes.

Knowledge verification cycle

The existing specialists were extended too: a full Enforce Script reference, Dabs and widget UI coverage, a texture and material cookbook, model and LOD rules, animated doors, a spec step in /dayz-init before building, and /dayz-layout-preview for several screen sizes.

Specialist procedures

Each specialist's steps inside the team loop described in "Gates". Specialists that write DayZ content look up vanilla first, as described in "RAG search". dayz-build-engineer, dayz-docs-writer, dayz-build-checker, dayz-ingame-tester and figma-node-normalizer have no RAG tools; they work from the mod, its logs or the Figma file.

SpecialistProcedure
Script lead
dayz-script-specialist
  1. Searches the vanilla scripts for the class it will change and reads the real file.
  2. Writes a modded class in the right layer (3_Game, 4_World or 5_Mission) and calls super.
  3. Adds RPCs only where client and server must talk, and checks which side runs each line.
  4. /dayz-lint and the build gate check and pack it (nothing compiles Enforce Script there); the in-game gate catches compile errors and reads script.log.
dayz-workbench-specialist
  1. Reads how vanilla Workbench plugins are registered.
  2. Writes the plugin script and its tool panel.
  3. Never opens Workbench itself: it tells the user to open it with /dayz-launch-workbench --mod <ModName>.
  4. Returns the plugin and the steps to load and run it.
dayz-persistence-specialist
  1. Lists every value that must survive a restart.
  2. Writes OnStoreSave and OnStoreLoad, with a version number written first.
  3. Adds an upgrade path so saves from the last version still load.
  4. Runs the data audit: every field is written and read back in the same order.
  5. Hands the audit to the server lead before release.
dayz-ai-specialist
  1. Studies how vanilla infected and animals decide what to do.
  2. Writes the behavior as its own script classes, never copied from another mod.
  3. Gives the server lead the spawn setup.
  4. In-game test watches the behavior and server performance.
Config lead
dayz-config-specialist
  1. Finds the closest vanilla parent class (Grep for known names, RAG search for questions by meaning) and reads its definition on disk, cited as path:line.
  2. Writes CfgPatches with the right requiredAddons, then the class itself.
  3. Matches hiddenSelections to the names in the model.
  4. /dayz-lint and the build gate check it loads.
dayz-vehicle-specialist
  1. Picks the closest vanilla vehicle as the parent.
  2. Writes the vehicle class and its simulation: engine, gearbox, axles, wheels.
  3. Adds attachment slots for doors, hood, trunk, wheels, battery and plug, and the fluids.
  4. Writes the CarScript or BoatScript class for seats, doors and damage.
  5. Gives the server lead a types.xml entry; the behavior gate spawns it and a person-run checklist covers driving.
dayz-weapon-specialist
  1. Picks the closest vanilla weapon as the parent.
  2. Writes the weapon, magazine and ammo classes and the attachment slots.
  3. Sets recoil and fire modes.
  4. Lists the model selections and memory points the art lead must provide.
  5. The behavior gate spawns it and fits each attachment; a person-run checklist covers firing and reloading.
Art lead
dayz-object-builder
  1. Specifies the LODs (visual, geometry, fire geometry, view geometry and memory) as numbered Object Builder steps; the user builds them, since it cannot edit a .p3d.
  2. Names the selections and memory points the config and animations need, and writes model.cfg.
  3. Runs /dayz-p3d-audit after the user saves the model.
  4. Hands the selection names to the config lead.
dayz-asset-specialist
  1. Checks each texture has the right suffix (_co, _nohq, _smdi and the rest).
  2. Packs them with /dayz-pack-texture.
  3. Writes the .rvmat for each material.
  4. Writes a look checklist for the user to check in Object Builder or in game; it never launches either.
dayz-wearables-specialist
  1. Picks the inventory slot and the closest vanilla item as the parent.
  2. Sets slots held, protection and insulation.
  3. Sets hidden selections so one model carries every color.
  4. Notes the proxy positions for the Object Builder specialist.
  5. The behavior gate wears each color class; a person checks in game how each color looks.
dayz-animation-specialist
  1. Lists the moving parts and their bones.
  2. Writes skeletonBones for the moving parts and the class Animations block in model.cfg; the Object Builder specialist keeps the rest of model.cfg.
  3. Gives the user the bone and selection names for their own Blender export.
  4. Names the script hook that plays the animation; the script specialist writes that code, and the in-game test uses it.
UI lead
dayz-ui-specialist
  1. Reads the vanilla layout closest to the new screen.
  2. Writes the .layout and the script class that drives it.
  3. Builds icons into an imageset with /dayz-build-imageset.
  4. The layout checker checks it against the Figma-to-DayZ rules and /dayz-layout-preview draws it; the in-game test opens it.
figma-node-normalizer
  1. Reads the Figma frame.
  2. Cleans layer names and structure so they map to DayZ widgets.
  3. Hands the clean tree to the layout converter.
figma-to-dayz-layout
  1. Turns the clean tree into a DayZ .layout.
  2. Uses only widget types the game supports.
  3. Hands it to the layout checker.
Server lead
dayz-server-admin
  1. Writes types.xml entries with /dayz-edit-types.
  2. Adds events, spawn points and gameplay settings where needed.
  3. Splits large economy files with /dayz-split-types.
  4. Sets up a missing test server instance with /dayz-add-server (it starts nothing), and gives you the /dayz-launch-test command instead of starting the server itself.
dayz-map-specialist
  1. Writes layers.cfg and the surface and clutter configs; if it needs the user's own layers.cfg and it is missing, it stops and asks for it.
  2. Gives numbered steps for the DayZ Editor export and the Terrain Builder import and generation, which the user carries out.
  3. Returns the files and the steps to rebuild the map.
Release lead
dayz-build-engineer
  1. Packs the mod with /dayz-build-pbo.
  2. Starts the test session with /dayz-launch-test.
  3. Reports the build result to the release lead, who passes it to the orchestrator.
dayz-docs-writer
  1. Reads what changed in the wave.
  2. Updates the README, changelog and classname list.
  3. With /dayz-release-pack, writes the Workshop text and server-owner notes.
Any lead
dayz-audio-fx-specialist
  1. Reads the vanilla sound or particle closest to the request.
  2. Writes the sound shader and sound set, or the particle with /dayz-particles.
  3. Adds the script line that plays it.
  4. In-game test listens and looks.
dayz-physics-specialist
  1. Reads the model's geometry LODs and mass.
  2. Finds the fault: missing geometry, wrong mass or bad collision.
  3. Hands the fix to the Object Builder or config specialist; it never edits.
  4. A person-run in-game test drops, throws and shoots it, which the behavior gate cannot.
Checks and fixes
dayz-mod-reviewer
  1. Reads the finished task against the DayZ rules file.
  2. Lists each problem with the specialist who owns it.
  3. Never edits files.
dayz-layout-validator
  1. Checks the .layout against the Figma-to-DayZ rules: file format and widget classes.
  2. Reports PASS or FAIL with each problem and its line. Never edits.
dayz-build-checker
  1. Runs only when /dayz-gate build itself breaks.
  2. Reads the AddonBuilder output and names the failing file.
dayz-ingame-tester
  1. Runs only when /dayz-gate ingame itself breaks.
  2. Reads the logs from the test session and reports what failed.
dayz-mod-debugger
  1. Gets new errors that triage does not know.
  2. Reads script.log, RPT and crash files back to the line that failed.
  3. Reports the cause, evidence, location and fix to whoever called it (the orchestrator or a lead), naming the worker agent that owns the fix.

Paste-in routing

The UserPromptSubmit hook paste_router.py recognizes what you paste and adds context that points Claude at the matching workflow. It never blocks a prompt.

Pasted inputResult
Crash log, RPT or script.log linesTriaged in the hook against the /dayz-gate known errors: cause and fix for known lines; new lines go to dayz-mod-debugger.
Screenshot of a bugThe hook suggests a specialist: UI problems to dayz-ui-specialist, texture or material problems to dayz-asset-specialist, an error message or wrong behavior to dayz-script-specialist. The dayz-router agent sends an on-screen error message to dayz-mod-debugger (or gate triage) instead, so the two can disagree on that case.
Figma linkRuns the Figma pipeline and returns a checked .layout.
GitHub linkPoints at /dayz-import-mod --source <link>, which imports the mod into workspace\ and can add the missing standard pieces.
Steam Workshop linkRefused with the reason: Workshop content is packed, binarized and often protected.
types.xml chunkChecks the entries, lists any problems and points at /dayz-edit-types --merge.

Prompt caching is left to Claude Code, which handles it itself; Agentic-Z has no rule or test for it. The behavior and visual gates are tested with fixtures only and have not run in a live DayZ session yet.

Add-ons (planned)

An optional agentic-z-addons plugin is planned for outside tools such as Blender, an AI 3D generator or another MCP server. No add-on ships yet; the plugin marketplace lists only agentic-z and agentic-z-panel. Each add-on will be a workflow that connects the outside tool at one point in the loop, usually handing a finished model to dayz-object-builder, so the normal gates check it like any other work. Planned rules:

  • Opt-in: the core never loads an add-on the user has not installed.
  • Same gates: add-on output goes through the mod review, the build gate and the in-game gate.
  • No reverse engineering: no add-on unpacks protected mods or converts binarized models back to editable ones.

Quality

Every agent, skill and shared file was graded by independent Claude reviewers against the code on develop, fixed and regraded until no reviewer found a defect.

  • Grades: 164 of 164 items at A+ (30 agents, 44 skills, 90 shared files).
  • Tests: 2,884 collected by py -m pytest -q .claude scripts/dev hooks, plus 18 panel tests; CI runs them on every pull request and on every push to develop and main.
  • Answer tests: evals/ covers 23 of the 30 agents; a change may only keep or raise a score.

The grading method, every grade with its reason, and the defects grading found are in the Agentic-Z Agent Team document.

44 skills (slash commands) that agents and users can run. 40 ship in the plugin; /sync-skills, /agentic-z-update, /docs-sync and /clean-repo are clone only.

  • Environment check: 18 of the 40 plugin DayZ skills run /dayz-preflight first (preflight itself is the check).
  • Exceptions: the Tier 2 rules file has 14 exception entries naming 21 skills, each with its reason. /dayz-lint, /dayz-balance, /dayz-conflict-check, /dayz-recipe, /dayz-layout-preview and /dayz-upgrade-guard still read P: but only read files and write a report; /dayz-ask only checks that P: is mounted; /dayz-gate gates through the scripts it calls; /dayz-stop-test skips the check.
  • Reference only: /dayz-particles has no script.

Permissions and safety

  • Shipped permissions (clone only): .claude/settings.json allows the repo's own skills and scripts, plus npm install and npm ci from the lockfile. It denies python -c, python -m, node -e, node -p, npx, and npm install or npm i with a package name. Other inline forms such as py -c are not on the allow list, so they prompt first. A plugin install does not get this file, because plugins cannot ship permissions.
  • Agent tools: every agent has an explicit tool list. The five gates (dayz-mod-reviewer, dayz-layout-validator, dayz-build-checker, dayz-ingame-tester and dayz-mod-debugger) have no Edit or Write tools; four of them have Bash to run their checks, and only the debugger has no Bash.
  • Network access: agent-creator has WebFetch, and figma-node-normalizer uses the remote Figma MCP tools. The 21 agents that use RAG search send query text to the hosted Voyage AI API through search_dayz_source. With TYPESAFE_API_KEY set, /dayz-route sends the request text to api.typesafe.ai for Jev.
  • Scope lock: /dayz-scope-mod <ModName> blocks edits to every other mod in workspace\ (start Claude Code from the project root); --clear lifts it.
  • Cleanup: cleanup removes only what the toolkit made, and destructive steps ask first or need --yes.

FAQ

QuestionAnswer
Does it cost money?Agentic-Z is free to use for DayZ mods (see LICENSE). You need your own AI tool (see "Overview" for what each one supports). RAG search needs a Voyage AI key: the last full index build embedded about 66M tokens, and the current indexer makes more chunks, so check Voyage pricing. The prebuilt index from /dayz-search-download avoids the build cost; see "RAG search".
Will it touch my other mods?No skill writes to your other mods. Besides your mod, its P: link, its test server and its build folder, skills write only the state listed in "File layout". /dayz-scope-mod <ModName> also blocks edits to every other mod in workspace\.
Does it publish to the Workshop?No. Builds land in P:\Mods\@<ModName>, which the launcher loads. Publish with DayZ Tools Publisher.
Can I work on several mods?Yes. Each mod lives in workspace\<ModName>. Select "Set up or switch to another mod" in the /dayz-init hub.
Is it safe to run?See "Permissions and safety".
