# Agentic-Z 1.6.0

Minor release. Adds a Figma-to-DayZ `.layout` pipeline. A private tool was removed in 1.6.0.

## What's new

### Figma-to-DayZ pipeline (3 agents + canonical rules doc)

Convert a Figma design into a valid DayZ `.layout` file by routing the design through three specialist agents that share one canonical rules document:

- **`figma-node-normalizer`** — fetches the Figma node tree via the Figma MCP, strips decorative wrappers, emits normalized JSON with semantic types and per-axis sizing metadata (`fill | hug | fixed`).
- **`figma-to-dayz-layout`** — converts the normalized JSON to a valid `.layout` file in DayZ's custom property-file format (class names ending in `Class`, bare `key value` properties, brace-nested children).
- **`dayz-layout-validator`** — strips any CSS-isms or XML-isms, verifies widget classes against vanilla, normalizes indentation.

The canonical rules live at `.claude/skills/_shared/figma-to-dayz-rules.md` (synced to `~/.claude/skills/_shared/` for cross-project access). All three agents cite it. Covers:

1. The format is not XML
2. Format cheat sheet
3. Figma to DayZ widget mapping (prefix authoritative, layer kind fallback)
4. Naming prefix taxonomy (`btn_`, `bar_`, `panel_`, `check_`, `slider_`, `drop_`, `list_`, `grid_`, `modal_`, `preview_`, `txt_`, `img_`, `edit_`)
5. Layout translation: anchors-first, spacers only for dynamic content
6. Coordinate translation (Figma px → DayZ `hexactpos`/`vexactpos` toggles)
7. Color translation (hex → `R G B A` floats)
8. Font translation (Figma fonts → SDF fonts)
9. Hard NO list (XML tags, `=`, CSS attributes, etc.)
10. Worked example: Figma frame → normalized JSON → output `.layout`

Two rules explicitly enforced because they cause the most visible bugs:

- **Prefix is authoritative.** A Figma frame named `Btn_close` is `ButtonWidgetClass` regardless of layer kind (frame, rectangle, auto-layout container). Case-insensitive.
- **Fill Container → responsive width.** Figma Fill Container width emits `hexactsize 0` with `size 1` (relative, full parent). Pixel widths only for Hug Contents and Fixed.

### `dayz-ui-specialist` auto-routes Figma input

When the user's input is a Figma URL, fileKey, or node ID, `dayz-ui-specialist` now dispatches the three-agent pipeline before polishing. Users no longer need to invoke the figma agents by name. Top-level `CLAUDE.md` / `AGENTS.md` / `GEMINI.md` route Figma-to-DayZ work through the pipeline too.

The specialist's tool surface gained the Figma MCP tools (`mcp__plugin_figma_figma__get_design_context`, `get_metadata`, `get_screenshot`, `get_variable_defs`) and the `Agent` tool for dispatching the pipeline.

## What's gone

### A private tool was removed

A private tool was removed in 1.6.0. The public template no longer ships it, and its references were removed from the docs, the plugin manifest and the lint configs.

Skill count drops from 26 to 25.

## Upgrading from 1.5.0

`/plugin update agentic-z` will fetch the new version. If you have an active Claude Code session, restart it after the update so the new agent definitions and tool lists load.

If you have a clone of the repo, `/agentic-z-update` surfaces the diff (new agents, new rules doc, the removed private tool, version bump) for clean merging.

## Verification

After upgrade, a sanity check:

1. Start a fresh Claude Code session.
2. Ask: "list the tools the dayz-ui-specialist agent has access to."
3. You should see 14 tools, including four `mcp__plugin_figma_figma__*` entries and the `Agent` tool.

If you still see only 9 tools, the plugin cache needs a manual refresh: `/plugin update agentic-z` then restart.
