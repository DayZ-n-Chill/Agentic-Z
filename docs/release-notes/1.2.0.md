# Agentic-Z 1.2.0

Second feature release after the 1.0.0 / 1.0.1 / 1.1.0 line. Headline change is the smart `/agentic-z-update` three-way merge that protects user customizations during template pulls, plus the SessionStart hook that nudges when upstream is ahead. Skill renames are breaking but mechanical.

## Highlights

### Smart `/agentic-z-update` (three-way merge)

Replaces the destructive `git checkout` overwrite with a per-file three-way merge that respects user customizations. Every template-managed file is classified as one of: `unchanged`, `safe-overwrite`, `new`, `local-only-edit`, `conflict`, `deleted-clean`, `deleted-conflict`. Safe stuff applies automatically; conflicts default to leave-alone with `--per-file` for interactive resolution.

New flags: `--check`, `--quiet`, `--yes`, `--per-file`. Persistent baseline at `.claude/.upstream-baseline`. PID-based concurrency lock at `.claude/.upstream-update.lock`.

### SessionStart hook for upstream-ahead nudges

`.claude/settings.json` runs `update.py --check --quiet` on every Claude Code session start. Silent on no-change, single-line nudge on drift, fail-open on network errors. Completes in under 5 seconds even on large repos.

### Voyage AI free-tier projection check

`/dayz-search-index` and `/dayz-search-wiki-index` now estimate the build's tokens before the embed phase and warn if cumulative monthly usage would exceed 80% of the 200M-token Voyage free tier. Tracks usage in `~/.claude/dayz-search-index/usage.log`. New `--ignore-tier-warning` flag for CI.

### Search-index release-tag check

The same SessionStart hook also surfaces newer prebuilt index releases on GitHub. Read-only, never auto-downloads.

### Security baseline for shipped agents

All 12 agent definitions tightened: explicit `tools:` allowlists, `maxTurns` caps, valid colors, stripped commentary blocks. Reviewer and debugger agents get `permissionMode: acceptEdits`.

## Upgrading from a pre-1.2.0 clone

If you're on a clone older than this release, your local `update.py` has a Unicode bug that crashes Windows cp1252 consoles when it tries to print the changelog box characters. To get past it, run the upgrade with `PYTHONIOENCODING=utf-8`:

```cmd
set PYTHONIOENCODING=utf-8 && python .claude\skills\agentic-z-update\update.py
```

Once the upgrade completes, the new `update.py` no longer prints those characters and future runs are clean. The shipped `scripts/agentic-z-update.bat` wrapper sets the env var automatically, so subsequent invocations through that wrapper just work.

After the upgrade, you may see leftover folders from renamed skills in your working tree (the old `git checkout`-based merge didn't delete files removed upstream). Run `python .claude\skills\agentic-z-update\update.py --check --per-file` to walk through them and pick "take" to clean each one up.

## Breaking changes

- Skill names listed in the rename table above. References to old names (in your own scripts, hooks, agent prompts) need updating.
- On-disk RAG index path moved. If you migrated manually, no action. If you didn't, run `/dayz-search-download` to re-fetch or `/dayz-search-index` to rebuild.

## Compatibility

- Python 3.8+ (stdlib only for the auto-update path; no new third-party deps)
- Windows / macOS / Linux for the agent stack
- DayZ-specific skills are Windows-only (DayZ Tools dependency)
